# Independent Mac release binding

Roundlane adds Ed25519 release authentication with Apple's CryptoKit, using the same pinned public key as Windows. The private seed is read by the local signing tool from organizer-private and is never copied into the application. This is application-level authentication, not Developer ID, notarization or an external macOS trust anchor. A verifier running inside a fully replaced malicious application cannot independently prove its own trustworthiness.

The release manifest inventories regular files under Contents. Unknown/missing files and symlinks are rejected. Only the proof itself and Apple's outer CodeResources seal are excluded from this inventory. Resources are hashed directly. Each 64-bit Mach-O slice is hashed independently, covering all bytes before its final code-signature blob; LC_CODE_SIGNATURE offset/size and __LINKEDIT size bookkeeping are normalized to avoid a circular dependency between the embedded proof and Apple signing. Signature regions must be final, ranges/architecture tables valid, slices non-overlapping and unique. Linkedit file size must match the actual file and virtual allocation must remain within one 16 KiB page. Unsupported Mach-O formats fail.

The signing pipeline first applies hardened ad hoc signing, then generates the independent proof, then seals the application again. Native protection checks the pinned Ed25519 signature and full inventory on startup and periodic checks. An immutable authenticated manifest is retained within the process. Captured image bytes used for executable-memory comparison are also checked directly against that authenticated manifest, avoiding reliance on a separate earlier read of the image file.

Tests modify only setup/Roundlane-hardened-candidate.app and never enter kiosk. Ten cases in scripts/test-mac-release-binding.py: healthy; changed resource and renewed ad hoc seal; changed manifest and renewed seal; changed signature and renewed seal; missing proof and renewed seal; oversized signature and renewed seal; oversized manifest and renewed seal; added unknown file and renewed seal; modified own executable string and renewed seal; final original restoration. The modified executable test changes an unused failure-message string, not live instruction memory. Valid Apple ad hoc seals are explicitly verified before the independent guard is asked to reject the modified files.

Latest universal candidate passed all ten cases after strengthened canonical-format validation and direct authentication of the bytes used by the memory scanner. Safe self-test (17 contest-policy cases), five session-coordinator cases, settings initialization, actual WKWebView creation, six hardened/signature negative cases and the DYLD injection control/denial test passed. Final evidence is setup/mac-hardened-tests/release-binding-results.json, which must be read with its current timestamps. The public archive is still the earlier release. Actual production-hardened Mac instruction mutation, terminal native UI/OS recovery, Windows service-required rehearsal and final source/license packaging remain outstanding.

Sources consulted: https://sparkle-project.org/documentation/ and https://sparkle-project.org/documentation/security-and-reliability/ (EdDSA release signing, signature bypass fixes, and private-key command-line exposure). No Sparkle source or updater/XPC service is included; CryptoKit supplies the cryptographic implementation.

## Isolated live instruction-memory test

`scripts/test-mac-memory-scanner.py` extracts the exact production scanner helpers into a disposable arm64 fixture and supplies an explicitly fake independent-release hook. Only that fixture is signed with the unsigned-executable-memory exception; the production app retains empty entitlements. The fixture changes its own isolated instruction page to writable/nonexecuting (scanner rejects rights), modifies an instruction byte, restores read/execute (scanner detects changed code), then restores the original instruction (scanner accepts again). All four observations passed in setup/mac-hardened-tests/memory-scanner-results.json. This verifies scanner detection after a mutation is permitted; it does not demonstrate bypass of the production hardened runtime or cover Intel.

Initial fixture layouts shared a page with imported-function stubs; removing execution caused SIGBUS before the next report. A dedicated, page-sized instruction section isolated the controlled mutation. No application or OS protection was weakened to resolve that fixture layout problem.

Manifest/signature and inventory reads now have explicit allocation limits, including streamed reads for untrusted proof/resources. Native image reads are capped before allocating. The final bounded-read universal candidate passed the ten release cases, isolated scanner mutation/restoration, live five-second resource detection, five session cases and real WKWebView creation. Evidence build log: setup/roundlane-mac-bounded-release-build.log.
