# Собственная защита Roundlane

Цель пользователя: максимально практичная собственная защита самостоятельного экзаменационного приложения Windows/macOS, с исследованием похожих проектов. Условия: сохранить минимальный интерфейс, ручной старт, выход по коду, восстановление после сбоя; никогда не запускать kiosk на рабочем Mac. Проверять изменения в отдельных процессах и Windows VM.

## Модель угроз и результат

Участник работает без администратора и не должен менять компоненты, внедрять посторонние DLL или исправлять исполняемый код приложения. Форма организатора не является единственным местом проверки: native Runtime и Client проверяют подписанный комплект и собственную память. Непроверенный комплект не начинает экзамен. Нарушение во время экзамена закрывает доступ к заданиям до ввода кода организатора; после подтверждения выполняется штатный выход, без продолжения с нарушенной целостностью. Восстановление ОС сохраняется.

Администратор/ядро/изменённая ОС находятся вне границы доверия пользовательского приложения. Никакие собственные драйверы, отключение антивируса, удаление пользовательских файлов или скрытый автозапуск не добавляются. Нет утверждения о полной защите от любого внедрения или точном повторении SEB.

## Слои

1. Существующая Ed25519 подпись списка SHA256, открытый ключ закреплён в обоих frontend/native компонентах. Ключ подписи вне пакетов. Проверка повторяется в native Runtime/Client; основные читаемые компоненты удерживаются открытыми без разрешения записи/удаления.
2. Windows: сверка исполняемых PE секций загруженных компонентов с подписанными файлами, применяются HIGHLOW/DIR64 relocations для ASLR, только таблица IAT маскируется как изменяемая загрузчиком. Неподдерживаемые форматы обрабатываются явной ошибкой. Для собственных модулей контролируются writable executable страницы и MEM_IMAGE принадлежность.
3. Windows: новые модули проверяются по пути/подписанному manifest. Каталоги ОС Windows доверяются в рамках доверенной установленной ОС; для библиотек вне приложения/ОС нужен проверенный Authenticode и явная политика совместимости. Скрытые manual-map/private executable участки не объявляются полностью покрытыми: JIT .NET/CEF требует динамической памяти.
4. Windows: CLR/native debugger признаки и периодические проверки обоих процессов. Сигнал нарушения Runtime передаётся Client через изолированное именованное событие; сигнал лишь блокирует задания и не открывает desktop. Client требует код, затем штатно завершает сессию. Неизвестный результат проверки тоже останавливает доступ.
5. Mac: hardened runtime и минимальные entitlements; подпись/resources, загруженные образы и стабильные executable сегменты контролируются системными API. Apple-подписанные shared-cache образы учитываются отдельно. Запрет DYLD injection, writable executable image и debugger в экзамене проверяется безопасным self-test. JIT WebKit работает в системных дочерних процессах. Ad hoc сборка не объявляется Developer ID/нотариализованной.
6. Здоровье проверки/восстановление: никаких молчаливых успешных результатов при ошибке, краткая причина в журнале, защищённый выход/Recovery не удаляется. Оптимизируются частота и объём чтения без замены доказательства начальными snapshot'ами недоверенной памяти.

## Проверка и поставка

В изолированном процессе: валидный пакет, подпись отсутствует/подменена, изменённый файл+новый хеш, добавленная DLL, посторонняя загруженная DLL, writable executable image, изменение кода read-only image, корректное восстановление памяти и нормальные повторные проверки с JIT. Тесты повреждают только собственные тестовые компоненты в VM.

Native protected Windows: нормальный запуск браузера, сайт, отсутствие ложных срабатываний, сигнал нарушения -> lock screen, неверный код не разблокирует, правильный код -> восстановленный desktop; также чистый штатный выход. Mac: безопасные self-tests и WebView, mutation отдельной тестовой программы, проверка подписи; host kiosk не запускается. Непроверенные реальные x64/Intel машины отмечаются отдельно.

Один обновлённый архив Windows/Mac + полные покрытые исходники/лицензии/инструкция/отчёты. Предыдущий комплект сохраняется. Приватные аккаунты/пароли/seed не входят в публичные файлы. Goal завершён только после проверки доступных платформенных требований и явной фиксации реальных ограничений; ни промежуточный scanner, ни один тест не заменяют интеграцию.
